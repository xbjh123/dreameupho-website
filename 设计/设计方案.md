## 1. 设计理念

**一句话定位：「一页被春风吹开的乐谱，飘在北宇治的蓝天里。」**

整个网站被当作「一部组曲」来编排：每个内容区块是一个**乐章（Movement）**，五线谱是贯穿全站的视觉动线，云朵制造空气的层次，黄铜色乐器光泽作为唯一的暖色点缀。整体气质是明亮、有呼吸感的青春，而不是模板化游戏站常见的深色炫酷或满屏卡片堆砌。

**关键词（5 个）：**

1. **青空** —— 大面积白 + 天蓝渐变，空间通透，永远像午后窗台的光
2. **乐谱动线** —— 五线谱贯穿区块之间，音符是唯一的装饰性主角
3. **呼吸感** —— 大留白、宽行距、宽间距，文字段落宁可短不可挤
4. **破框立绘** —— 人物立绘超出卡片边界，像从乐谱里走出来
5. **乐器金** —— 唯一暖色，只出现在最关键处（CTA 细节、当前选中态、音符点缀）

**与模板站的区分点（必须做到）：**

- 全站区块编号采用「MOVEMENT 01–06」乐章叙事，而非普通的 Section 01
- 页面滚动进度条是一条五线谱，一个 ♪ 随滚动沿谱面前进
- 区块之间用云朵轮廓过渡，不用生硬直线
- 神秘角色「????」（真由）的卡片做差异化悬念设计
- 横幅分区标题不是简单贴图，而是叠加「乐章编号 + 五线谱 + 漂移云」的组合页头

| 主色·深 | 低音蓝 Euph Deep | `#0F3D6B` | 页脚背景、Hero 渐变顶、深蓝底区块 |

| 功能 | 标签底 Tag BG | `#E8F2FC` | 资讯标签、chips 底色 |

### 2.2 渐变定义

| 名称 | 定义 | 用途 |
|---|---|---|
| 青空渐变 G-Sky | `180deg, #0F3D6B 0% → #1E6FBA 45% → #4A90D9 75% → #BFE0F7 100%` | Hero 背景（自上而下由深蓝化入浅蓝，底部接白云） |
| 浅蓝渐变 G-Mist | `180deg, #FFFFFF 0% → #F5F9FD 100%` | 区块间过渡 |
| 金色微光 G-Gold | `90deg, #F2B33D → #FBD98A` | CTA 上的音符图标、选中态下划线 |
| 夜幕渐变 G-Night | `180deg, #0F3D6B → #0A2C4F` | 页脚 |

### 2.3 使用规则与占比

- **白/晨雾白 ≈ 55%**（背景）、**蓝系 ≈ 35%**（结构、文字、渐变）、**金 ≈ 5%**（点睛）、**墨蓝文字 ≈ 5%**（量级随文本）。
- 乐器金只允许出现在：主 CTA 上的音符、当前导航下划线、语言切换选中态、资讯标签中的「招募」类标签、个别点缀音符。**禁止**大面积金色块。
- 深蓝（`#0F3D6B`）只用于 Hero 顶部、页脚、移动端菜单三处「收束性」区域，正文区永远浅底，保持通透。
- 同一屏内蓝色层级不超过 3 层（主蓝/中蓝/浅蓝），避免脏。

## 3. 字体系统

### 3.1 字体栈（不依赖被墙的在线字体）

**策略：自托管两个字体的 woff2 子集放 `assets/fonts/`，系统字体兜底。禁止引用 Google Fonts 域名字链。**

| 用途 | 字体栈（按优先级） |
|---|---|
| 中文标题 | `Noto Sans SC → Source Han Sans SC → 思源黑体 → PingFang SC → Hiragino Sans GB → Microsoft YaHei → sans-serif` |
| 中文正文 | 同上（与标题同族，靠字重拉开层级） |
| 英文/数字展示 | `Quicksand → Noto Sans SC → PingFang SC → sans-serif`（Quicksand 圆润有青春感，专用于标语英文、乐章编号、按钮英文、大号数字） |
| 英文正文 | `Noto Sans SC → Segoe UI → Helvetica Neue → sans-serif` |

- 自托管建议：Noto Sans SC 子集化（仅简体常用字，字重 400/500/700/900，控制在 1MB 内）；Quicksand 全字符（仅拉丁，字重 500/700，小于 50KB）。
- 若当前阶段不做自托管，直接走系统字体栈也能成立（PingFang / 微软雅黑表现可接受），Quicksand 缺席时英文用同族黑体不影响大局。
- 装饰性「♪」符号直接使用 Unicode 字符（♪ ♫ ♩），不依赖图标库。

### 3.2 字号阶梯（桌面 / 移动）

| 层级 | 桌面 | 移动 (<768px) | 字重 | 行高 | 说明 |
|---|---|---|---|---|---|
| Hero 主标语 | 56px | 34px | 900 | 1.2 | 「通向未来的旋律♪」 |
| Hero 英文副标语 | 20px | 15px | 500，字距 0.35em，全大写 | 1.4 | A MELODY TOWARD THE FUTURE |
| 区块大标题 | 38px | 28px | 700 | 1.3 | 无横幅的区块用文字页头（资讯） |
| 乐章编号 MOVEMENT 01 | 14px | 12px | 700，字距 0.3em | 1 | Quicksand，主蓝色 |
| 卡片标题 / 角色名 | 24px | 20px | 700 | 1.3 | |
| 正文 | 16px | 15px | 400 | 1.9 | **行高 1.9 是呼吸感的关键，不许缩小** |
| 正文·次要 | 14px | 13px | 400 | 1.8 | 日期、说明、档案字段 |
| 按钮 | 16px | 15px | 700 | 1 | 字距 0.05em |
| 导航链接 | 15px | — | 500 | 1 | |
| 页脚小字 | 13px | 12px | 400 | 1.7 | |

### 3.3 字重使用规则

- 900 仅用于 Hero 主标语；700 用于标题/按钮/角色名；500 用于导航与英文展示；400 用于正文。
- 中文不使用斜体；英文副标语可全大写 + 宽字距制造「乐谱标记」感。

## 4. 布局系统

### 4.1 容器与栅格

| 项 | 值 |
|---|---|
| 内容容器 | max-width `1160px`，左右内边距 24px，居中 |
| 人物区块容器（特例） | max-width `1280px`（主角卡需要更宽舞台） |
| 窄文本容器（故事/介绍/资讯正文） | max-width `760px`，居中 |
| 栅格 | 桌面 12 列心智模型，实际用 flex/grid 实现；列间距 24px |

### 4.2 间距标尺（8 的倍数 + 两个呼吸档）

`4 / 8 / 16 / 24 / 32 / 48 / 64 / 96 / 128`

| 场景 | 值 |
|---|---|
| 区块上下内边距 | 桌面 `96px` / 移动 `64px` |
| 区块标题与正文间距 | `48px` / 移动 `32px` |
| 卡片网格间距 | `24px`（配角网格可 `16px`） |
| 卡片内边距 | `32px` / 移动 `24px` |
| 段落间距 | `24px` |
| 元素最小间距 | `8px` |

### 4.3 圆角规范

| 元素 | 半径 |
|---|---|
| 大卡片 / 人物卡 | `24px` |
| 内容卡片 / 资讯项 | `16px` |
| 标签 chip | `999px`（全圆角） |
| 按钮 | `999px`（胶囊形，呼应云朵的柔软） |
| 图片容器 | `16px` |

### 4.4 阴影规范（全部带蓝调，不用纯黑阴影）

| 名称 | 值 | 用途 |
|---|---|---|
| S-卡片静置 | `0 4px 24px rgba(30,111,186,0.08)` | 卡片默认 |
| S-卡片悬停 | `0 12px 40px rgba(30,111,186,0.16)` | hover 浮起 |
| S-导航 | `0 2px 16px rgba(15,61,107,0.06)` | 固定导航 |
| S-CTA | `0 6px 20px rgba(30,111,186,0.35)` | 主按钮 |
| S-立绘投影 | `0 8px 24px rgba(15,61,107,0.18)` | 破框立绘底部 |

### 4.5 响应式断点与行为

| 断点 | 范围 | 关键行为 |
|---|---|---|
| 桌面 | ≥ 1200px | 完整布局；主角卡 2 列；配角 4 列；导航全展开 |
| 平板 | 768–1199px | 主角卡 2 列（卡片内左右结构改为上下）；配角 3 列；间距缩 20% |
| 手机 | < 768px | 全部单列；配角 2 列网格；导航变汉堡；Hero 标语 34px；区块内边距 64px |
| 超宽 | ≥ 1600px | 容器不再增宽，背景云朵装饰延伸，避免内容被拉散 |

## 5. 组件规范

### 5.1 顶部导航栏

- **结构**：左（Logo 组合）｜中（锚点链接：游戏介绍 / 故事背景 / 人物介绍 / 制作成员 / 资讯）｜右（语言切换 + 「加入我们」小 CTA）。
- **尺寸**：高 64px；桌面内边距左右 32px；固定顶部，滚动时始终可见。
- **背景**：`rgba(255,255,255,0.85)` + 背景模糊 12px（毛玻璃），底部 1px `rgba(30,111,186,0.08)` 分隔线 + S-导航阴影。Hero 区间内导航自身仍是半透明白底，文字对比度安全。
- **Logo 组合**：项目两版 Logo 均为白色 PNG，**不能直接放浅底**。方案：Logo_b（上低音号图标）置于 `36×36px`、圆角 10px、填充主蓝到中蓝斜向渐变的圆角方块内；右侧两行文字——上行「DreamEupho」Quicksand 700 16px 主蓝，下行「梦想悠风」11px 雾灰蓝、字距 0.2em。
- **链接态**：默认雾灰蓝 500；hover 变主蓝 + 下方出现 2px 金色短下划线（宽 24px，居中，0.2s 滑入）；滚动监听命中的当前区块链接保持主蓝 + 金色下划线常显。
- **「加入我们」按钮**：高 40px、内边距 0 20px、主蓝实心胶囊 + 白字 + 左侧 14px 金色 ♪；hover 上浮 -2px、阴影加深、♪ 旋转 -12°。

### 5.2 Hero 首屏

- **高度**：桌面 100vh（最小 640px）；移动 92vh。
- **背景**：G-Sky 全幅渐变（顶深底浅）；底部 1/4 处用两层云朵剪影（纯白，透明度 0.9 / 0.5 两层）交叠，向下自然融入晨雾白区块，**看不到生硬边界**。
- **内容**（垂直居中偏上约 42% 处，水平居中，文字全部白色）：
  1. Logo_a（白色横版完整 Logo）宽 280px（移动 200px），下方间距 32px
  2. 主标语「通向未来的旋律♪」，900 字重，结尾 ♪ 用乐器金 `#F2B33D`——全屏唯一的暖色焦点
  3. 英文副标语 `A MELODY TOWARD THE FUTURE`，宽字距全大写，透明度 0.85
  4. 间距 40px 后按钮组（水平排列，移动换行）：主按钮「加入制作组 →」（白底蓝字胶囊，S-CTA，hover 上浮）+ 次按钮「了解游戏 ↓」（1.5px 白色描边透明底，hover 背景 `rgba(255,255,255,0.15)`）
- **装饰层**：一条半透明五线谱（白色 12% 透明度，5 条 1px 线、间距 12px）横贯 Hero 中部；2–3 个白色 ♪（20–28px，透明度 20–35%）沿谱线以 20–30s 周期缓慢平移；云朵三层视差（滚动时位移差不超过 40px）。
- **底部**：居中「向下滚动」提示——12px 竖线 + ♪，1.6s 上下浮动动画，白色 60% 透明度。

### 5.3 CTA 按钮（全站统一）

| 类型 | 视觉 | 尺寸 | 状态 |
|---|---|---|---|
| 主按钮（深蓝底区域） | 白底、主蓝文字、胶囊 | 高 52px / 内边距 0 36px | hover 上移 -2px + 阴影加深；active 回落 |
| 主按钮（浅底区域） | 主蓝实心、白字、左侧金色 ♪ | 同上 | hover 背景变 `#4A90D9`，♪ 摆动 |
| 次按钮 | 1.5px 主蓝描边、主蓝文字、透明底 | 高 48px / 0 32px | hover 底色 `#E8F2FC` |
| 文字链接按钮 | 主蓝 + 右侧 → | 正文尺寸 700 | hover 时 → 右移 4px |

### 5.4 区块标题（乐章页头，详见第 6 节）

- 组合：`乐章编号（MOVEMENT 01）` + 横幅图 + 可选一句 14px 雾灰蓝引语。
- 编号置于横幅左上斜上方（向上偏移 -8px），Quicksand 700 主蓝，前面带一条 32px 长、2px 高的金色短横。

### 5.5 内容卡片（通用）

- 白底、圆角 16px、S-卡片静置、内边距 32px。
- hover：上移 -4px，阴影过渡到 S-卡片悬停，0.25s ease-out。
- 可选顶部 4px 渐变蓝装饰条（从 G-Sky 截取的中段蓝色），用于分组型卡片（制作成员、声明要点）。

### 5.6 人物卡片 · 主角（8 位）

- **布局**：桌面 2 列网格（间距 32px），卡片横向构图（对应 3840×2160 立绘源图，卡片高宽比约 16:10）；平板 2 列但卡片内改上下结构；手机单列。
- **卡片结构**（桌面左右式）：
  - 左 45% 信息区：角色名（24px 700 墨蓝）+ 名字下方 2px 金色短线（宽 32px）+ 档案字段（乐器 / 年级 / 声部等，14px，字段名雾灰蓝、值墨蓝，逐行排布）+ 一句简介（14px 雾灰蓝，2–3 行截断）
  - 右 55% 立绘区：背景 `#E8F2FC → #FFFFFF` 浅渐变；立绘**底部对齐、顶部破框**——立绘上缘超出卡片上边界 24–40px，像从卡片里走出来；立绘底部带 S-立绘投影
  - 卡片白底、圆角 24px；破框用「内层容器裁剪三边、顶部放行」实现
- **hover**：立绘以底部为基准放大 1.03，卡片上浮 -4px，信息区金色短线拉长至 48px。
- **特例 ·「????」（真由）**：悬念处理——立绘区压暗（`#0F3D6B` 40% 遮罩）呈逆光剪影感；角色名位置显示大号 `????`（Quicksand 700 主蓝），下方一行 12px 雾灰蓝 `AN UNKNOWN MELODY…`；卡片用 2px 虚线描边（`rgba(30,111,186,0.3)`）替代普通卡片边，营造「资料未解锁」感。**这是她的人设，全站只此一例。**

### 5.7 人物卡片 · 配角（21 位）

- **布局**：桌面 4 列 / 平板 3 列 / 手机 2 列，间距 16px。
- **卡片**：竖向小卡——上部立绘（源图 3507×1260 超宽，取**人物居中的 3:4 竖向裁切**，定位对准人脸/上半身，需逐张微调裁切定位参数并记录在数据文件中）；下部白色信息条：角色名 15px 700 + 一行 12px 雾灰蓝小字（乐器/职务）。
- 圆角 16px，白底，S-卡片静置；hover 立绘区叠 8% 白色渐显 + 卡片上浮 -3px。
- 「主要角色」与「配角阵容」两个子区块之间用五线谱分隔带过渡（见 6.3）。

### 5.8 资讯列表项

- **结构**（桌面横向）：左侧日期块（宽 72px：大号「日」28px Quicksand 700 主蓝 + 下行 `2026.08` 12px 雾灰蓝）｜中间标题（18px 700 墨蓝，hover 变主蓝）+ 摘要（14px 雾灰蓝，2 行截断）｜右侧标签 chip（招募=金底白字 / 更新=浅蓝底主蓝字 / 公告=雾灰蓝底白字）+ 12px › 箭头。
- 项间距 16px，整体在 760px 窄容器内垂直排列；每项白底圆角 16px，左侧 3px 透明边条，hover 边条变主蓝 + 卡片上浮。
- 移动端：日期块压缩为标题上方一行小字。
- 列表底部「查看全部 →」文字链接按钮（条目多于 5 条时出现）。

### 5.9 制作成员分组

- **布局**：Core Team 独占整行（4 张成员卡，桌面 4 列 / 移动 2 列）；其余职能组（Scenario / Voice Acting / Art / Programming / Music / Others）2 列卡片网格（移动单列）。
- **职能组卡片**：顶部 4px 渐变蓝装饰条 + 组名（英文组名 Quicksand 700 16px 主蓝 + 中文职能名 12px 雾灰蓝）+ 成员列表（14px，按「职位：人名」排列；人名用墨蓝 500；超长名单如 2D Art 28 人用顿号连排折行，不逐行，避免卡片过长）。
- **Core Team 成员卡**：圆角 16px 白卡；顶部 48px 圆形头像位（无头像素材时用 G-Sky 渐变圆 + 白色音符符号占位，四人分别用 ♪ ♫ ♩ ♬ 区分）；下方职位（12px 金色 700）+ 名字（16px 700）。

### 6.1 标准组合（适用：游戏介绍 / 故事背景 / 人物介绍 / 制作成员）

结构（自上而下）：乐章编号 → 横幅图 → 可选引语。

- 乐章编号 `─── MOVEMENT 01` 置于横幅左上斜上方（上移 -8px）：金色短横 32px + 主蓝 Quicksand 700 文字。

- 可选引语：横幅正下方 24px 处，14px 雾灰蓝居中。
- 移动端：横幅宽度 100%（左右留 16px 边距），圆角降为 14px；乐章编号缩小置于横幅正上方居中。

### 6.2 重要声明横幅（第 5 张）的用法

### 6.3 人物区块内的五线谱分隔带

## 7. 动效与交互（轻量，纯 CSS + 少量 JS）

| 场景 | 效果 | 参数 |
|---|---|---|
| 区块进入 | 内容 fade-up | 上移 24px → 0，透明度 0→1，600ms ease-out；同区块子元素交错 80ms |
| 触发方式 | IntersectionObserver，阈值 0.15，只触发一次 | 约 30 行原生 JS |
| 滚动进度 | 页面顶部 3px 五线谱式进度条：1 条主蓝细线 + 一个 12px 金色 ♪ 随滚动沿谱面前进 | 监听 scroll + requestAnimationFrame 节流 |
| 云朵视差 | Hero 与页头云层随滚动不同速率平移 | 位移系数 0.15 / 0.3 / 0.5，上限 60px |
| 漂浮音符 | Hero / 移动菜单 / 页头装饰 ♪ 缓慢漂移 | CSS keyframes 平移 + 轻旋转，周期 18–30s 各不相同 |
| 卡片 hover | 上浮 -4px + 阴影加深 + 立绘 1.03 放大 | 0.25s ease-out |
| 按钮 hover | 主按钮上浮 -2px；♪ 图标旋转 -12° | 0.2s |
| 锚点滚动 | 平滑滚动，目标区块顶部留 80px 偏移避开固定导航 | scroll-behavior + scroll-margin |
| 导航当前态 | 滚动监听高亮当前区块链接 | 复用 IntersectionObserver |
| 降级 | `prefers-reduced-motion: reduce` 时关闭全部位移动画，仅保留透明度渐变；云与音符静止 | **必须实现** |

**红线**：不做粒子特效、不做鼠标跟随、不做逐字打字机——与清新气质冲突且拖累性能。全站 JS 动效预算 < 100 行。

## 10. 双语方案

- **切换控件**：导航右侧 `中 | EN` 胶囊分段控件（见 5.11），全站唯一入口；移动端在菜单底部放同款。
- **作用范围**：切换后整页语言整体切换，包括——导航链接、区块标题、正文（游戏介绍 / 故事背景 / 声明三条）、按钮、页脚声明与版权、招募页全文。人物名为专有名词，中/英模式下分别显示「中文名 / 罗马音」（如 黄前久美子 / Kumiko Oumae）。
- **实现约定**：所有可切换文案的 DOM 节点挂 `data-zh` / `data-en` 双属性（或同结构 JSON 文案表），切换时 JS 批量替换并切换 `<html lang>`；选择结果存 `localStorage`，再次访问记住偏好。默认中文。
- **排版规则**：英文模式下正文字号不变、行高调至 1.8（英文 1.9 会显得稀）；英文副标语、乐章编号、按钮英文始终用 Quicksand 不随语言切换变化；英文文案较长时按钮允许增高到两行，卡片高度自适应，不做固定死高。
- **不做的**：不做中英对照同屏混排（破坏呼吸感），不做浏览器自动检测跳转（仅首次访问可按浏览器语言给一次默认，之后以用户选择为准）。
