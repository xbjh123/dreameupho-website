## B. 乐章式滚动（一节一节的内容动画）

### B.1 区块进入 = 一次"乐章表演"（强化现有 reveal）
每个区块进入视口（IntersectionObserver，阈值 0.2，触发一次）时，按序执行整节动画（总时长约 1.6s）：
1. **起拍（指挥棒扫过）**：见 §D，先做
2. **谱线写出**：页头五线谱带 scaleX 0→1（左原点，0.7s）——已有，保留
3. **排练编号方框**：pop 弹入（scale 0.8→1，0.25s）
4. **速度术语 + 标题 + 英文小字**：依次淡入（各 0.4s，交错 80ms）
5. **内容区**：卡片/文本以"纸张落定"（rotate 1.2°→0 + opacity）交错登场（每项 60ms），正文区微升 8px
- 人物区、成员区等大区块同样按此节奏，但卡片交错可以 40ms 更快些避免过长等待
- 已有 JS 的 `.reveal` 机制扩展：新增每区块的 `.mv-start` 门控（先起拍，再逐项）

### B.2 滚动步进感（轻柔，不锁死）
- body/scroll 容器加 `scroll-snap-type: y proximity`；每个主区块 `scroll-snap-align: start`（**proximity 非 mandatory**——人物区/成员区高于一屏，mandatory 会卡死）
- 效果：滚动到区块附近时轻微"吸附"到区块起始，配合起拍动画，形成"一节一节"的落地感，但不妨碍自由滚动

## C. 导航 Logo 直用内部图案（不裁圆形）

- **现状**：Logo_b 白色图标被裁进 40px 蓝色正圆容器（v3 起）
- **改为**：直接用 Logo 内部图案原形展示——由工程师先程序化检查 Logo_a（1260×460）/ Logo_b（367×387）的透明边界与内容分布，选择**视觉主体完整、无容器裁剪**的展示方式：
  - 优先方案：直接展示 Logo_a（横版完整标识，含图标+字标）原比例，导航内高度 34-40px（宽约 100-115px）；或若 Logo_a 含大留白/背景，则裁剪其内部有效内容区再展示
  - 若 Logo_a 不适用，则用 Logo_b 原形（方形图标，高 36px）不加圆形容器
- **双态可读性**（关键）：Logo 是白色 PNG——
  - 透明态（Hero 上）：白色 Logo 直接显示 ✓
  - 纸感态（滚动后白底）：白色不可见，用 **CSS filter 反色**（`filter: invert(1)`）使 Logo 变墨色（深蓝黑），"墨色标识印在节目单上"，与纸感态天然契合；hover 微调不必须
  - 两种 filter 状态由现有 `.nav.paper` class 切换，transition 0.3s 同步
- 品牌区右侧文字行（DreamEupho / 梦想悠风）保留（纸感态主蓝/雾灰蓝，透明态白）

## D. 出彩过渡：「指挥棒扫过」金线起拍

**概念**：每个乐章开始时，一道细金线（指挥棒）从页面左侧扫到右侧，划出"起拍"，随后该乐章内容开始表演——把"组曲"的叙事变成可感知的节奏。

**实现**：
- 每个主区块 `.section` 增加一个装饰元素 `.baton`（绝对定位，区块顶部偏上 40px，全宽 1.2px 金线，高 2px，圆头），初始 `transform: scaleX(0); transform-origin: left`，透明度 0
- 区块进入视口（同 B.1 触发点）时：`.baton` `scaleX 0→1`（0.55s，cubic-bezier(0.16,1,0.3,1)）＋ 透明度 0→1→0（金线扫过后淡出），随后立即开始 §B.1 的谱线写出等表演
- 金线扫过瞬间，区块背景（如晨雾白）可加一次 0.3s 的极淡白闪（opacity 0→0.06→0）增强"起拍"感（可选，若实现成本低）
- Hero 与第一个区块之间、招募 CTA 与页脚之间同样加一次起拍
- 移动端：起拍线宽度 80%（居中），或按区块宽度
- **prefers-reduced-motion: reduce**：`.baton` 与全部进入动画静止，内容直出（保持现有降级）

**为什么出彩**：不同于常见 scroll-reveal（淡入上移），"指挥棒扫过→乐章表演"把每次滚动进入变成一个完整的音乐小节拍，且与全站"组曲/总谱"叙事严丝合缝——这是本设计最有记忆点的交互时刻。
