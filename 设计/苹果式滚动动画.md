# DreamEupho 宣传网站 — 苹果官网式滚动动画方案

> 日期：2026-08-08
> 目标：把全站滚动体验升级为「苹果官网式」——滚动驱动、丝滑、有叙事节奏；保持乐谱/乐章主题
> 技术：CSS Scroll-Driven Animations（animation-timeline: view()，Chrome/Edge 115+ 原生）+ JS IntersectionObserver/rAF 降级；只用 transform/opacity，prefers-reduced-motion 全关

---

## 0. 苹果官网滚动动画的四个特征（本方案对应）

| 苹果特征 | 本方案落地 |
|---|---|
| 滚动驱动（内容随滚动进度渐进呈现，非一次性触发） | 区块内容按视口进入进度做 translateY/opacity/scale 联动 |
| Hero 视差与消退（滚离首屏时内容上移淡出、背景微缩放） | Hero 内容随滚动上移+淡出，背景 scale 1→1.06 |
| 分区钉住（sticky 标题/画面钉住，内容从下方流过） | 各乐章「总谱页头」滚动时粘在导航下方，内容从其下方流过 |
| 丝滑（GPU 合成、统一缓动、无抖动） | 纯 transform/opacity；CSS view() 原生驱动 + rAF 节流；ease 统一 |

---

## A. Hero 视差与消退（Apple 招牌）

- `.hero` 内容（Logo/标题/按钮）在滚动离开首屏时**上移 + 淡出**：`translateY(0→-80px)` + `opacity 1→0`，滚动范围约 60vh
- `.hero-bgimg` **轻微缩放** 1→1.06（视差纵深），滚动范围约 120vh
- 实现：CSS `animation-timeline: scroll()`（根滚动）或 JS rAF 按 scrollY/heroHeight 计算进度（更稳，兼容）
- 效果：像苹果产品页首屏那样「内容退场、背景拉开」，而不是生硬滚走

## B. 区块内容「滚动驱动」渐进呈现（替代一次性 reveal）

- 现状：`.reveal`/`mv-start` 是 IntersectionObserver 一次性触发（进视口触发一次）
- 改为**滚动进度驱动**：每个 `.fade-up`/内容块在其「进入视口」的过程中，随进入比例连续动画：
  - `opacity 0→1`、`translateY(48px→0)`、`scale(0.98→1)`，随元素进入视口的进度（entry 0%→100%）线性/缓动完成
  - 同区块元素可微错位（各元素 animation-delay 用负值在 timeline 上错开 5-8%），形成「依次浮现」的 Apple 节奏
- 技术：
  - 优先 CSS：`.fade-up { animation: fadeUp linear both; animation-timeline: view(); animation-range: entry 0% entry 95%; }`
  - 降级（不支持 view() 的浏览器）：现有 IO 一次性 reveal 保留
  - 已触发区块（语言切换重渲染）直接 `.in` 显示，不重放
- **总谱页头（乐章表演）保留**：baton 起拍 + 谱线写出 + 编号 pop 保持（这是全站识别度），但内容区改滚动驱动

## C. 分区粘性「钉住页头」（Apple 讲故事签名）

- 各乐章的「总谱页头」（`.score-head` 或所在 container）在滚动时**粘在导航下方**（top: 72px 左右），其区块内容从下方流过，直到本区块滚完才随区块走
- 实现：`.score-head { position: sticky; top: 72px; }`（在区块内 sticky）
- 效果：滚动到人物区时，总谱页头钉住、人物卡从下方流入——「翻开乐谱、内容流动」的叙事感，且与乐章编号/速度术语持续可见
- 注意：区块内部容器当前是 `position: relative` 结构，需确认 sticky 生效（父容器高度足够、无 overflow 裁剪）；人物区等大区块效果最佳；若个别区块 sticky 观感差（如资讯区矮），可只对 characters/credits 两个大区块启用

## D. 丝滑细节

- 统一缓动：`cubic-bezier(0.16, 1, 0.3, 1)`（Apple 常用的「快进慢出」）
- 滚动监听全部 passive + rAF 节流；动画只改 transform/opacity（Vercel 准则）
- 大面积动画元素（人物卡等）加 `will-change: transform`（数量控制，避免内存过载）
- `prefers-reduced-motion: reduce`：所有滚动驱动动画禁用（内容直出），sticky 保留（不属动效）

## E. 实施顺序与验证

1. A（Hero 视差消退）→ B（滚动驱动 reveal）→ C（sticky 页头）→ D（缓动/性能收尾）
2. 验证：Chrome headless/CDP 在多个 scrollY（0/600/1500/3000）截图，确认：
   - Hero 滚离时内容上移淡出、背景缩放
   - 内容块随滚动渐进呈现（截图中段元素处于动画中间态）
   - sticky 页头在区块滚动时保持在顶部
   - 无 console 错误、无布局抖动（rAF 节流）
3. prefers-reduced-motion 下无动画
